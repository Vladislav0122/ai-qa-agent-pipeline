# 🧪 Тестовая модель и Тест-кейсы (TMS Test Model)

## 1. Матрица тестового покрытия (Traceability & Technique Matrix)

| ID AC | Описание требования | Применяемая техника тест-дизайна | Кол-во тестов | Тип и обоснование проверок |
|---|---|---|---|---|
| SEC-101 (AC-1) | Успешная смена пароля (Happy Path) | Классы эквивалентности (EP) / Smoke | 1 | **Positive (UI)**: проверка успешного завершения основного сценария. |
| SEC-101 (AC-2) | Граничные значения длины (10–32 символов) | Анализ граничных значений (BVA) | 4 | **Boundary (UI/API)**: проверка точек `9`, `10`, `32`, `33` символов. |
| SEC-101 (AC-2) | Набор символов (буквы, цифры, спецсимволы) | Классы эквивалентности (EP) | 3 | **Negative (UI/API)**: пароль без цифр, пароль без спецсимволов, пароль только из цифр. |
| SEC-101 (AC-3) | Совпадение со старым паролем | Негативное тестирование / Таблица решений | 1 | **Negative (UI)**: новый пароль идентичен старому. |
| SEC-101 (AC-4) | Неверный текущий пароль | Негативное тестирование (Negative Flow) | 1 | **Negative (UI/API)**: ошибочный старый пароль при валидном новом. |
| SEC-102 (DoD-4) | Сохранение текущей сессии и отзыв сторонних | State Transition / Integration | 1 | **Positive (Integration)**: проверка доступности текущей сессии и разлогина на втором устройстве. |

> 📌 **Всего спроектировано**: 11 атомарных тест-кейсов. Количество тестов обусловлено не искусственными квотами, а математической необходимостью покрытия граничных значений (BVA) и классов эквивалентности (EP).

## 2. Детальные тест-кейсы для импорта в TMS

### [TC-SEC-001] Успешная смена пароля пользователем при валидных данных (Happy Path)
- **Приоритет**: Critical
- **Тип**: Positive
- **Слой**: UI
- **Трассировка**: `SEC-101 -> AC-1`
- **Предусловия**:
  1. Пользователь зарегистрирован с паролем `OldPassword123!`.
  2. Пользователь авторизован и находится на странице `/profile/security`.
- **Тестовые данные**:
  - Текущий пароль: `OldPassword123!`
  - Новый пароль: `NewSecretPass2026#` (18 символов, валиден)
  - Подтверждение: `NewSecretPass2026#`

| № | Действие (Step) | Ожидаемый результат (Expected Result) |
|---|---|---|
| 1 | Ввести `OldPassword123!` в поле «Текущий пароль» | Значение введено, символы маскируются |
| 2 | Ввести `NewSecretPass2026#` в поле «Новый пароль» | Значение введено, валидационные ошибки отсутствуют |
| 3 | Ввести `NewSecretPass2026#` в поле «Подтверждение» | Значение совпадает с новым паролем |
| 4 | Нажать кнопку «Сохранить изменения» | Отображается уведомление: *"Пароль успешно обновлен"*. Поля формы очищены. Текущая сессия активна. |

### [TC-SEC-008] Ошибка API: Неверный текущий пароль (HTTP 400)
- **Приоритет**: High
- **Тип**: Negative
- **Слой**: API
- **Трассировка**: `SEC-101 -> AC-4`
- **Запрос**: `PUT /api/v1/auth/password/change` с телом `{"currentPassword": "WrongPassword999!", "newPassword": "ValidSecret2026!"}`
- **Ожидаемый результат**: HTTP 400 Bad Request, тело `{ "error": "INVALID_CURRENT_PASSWORD", "message": "Указан неверный текущий пароль" }`.

### [TC-SEC-009] Проверка статуса сессий после смены пароля (Интеграционный сценарий)
- **Приоритет**: Critical
- **Тип**: Positive / Security
- **Слой**: Integration
- **Трассировка**: `SEC-102 -> DoD-4`
- **Предусловия**: Пользователь авторизован на Устройстве А (Desktop) и Устройстве Б (Mobile App).

| № | Действие (Step) | Ожидаемый результат (Expected Result) |
|---|---|---|
| 1 | На Устройстве А сменить пароль на валидный | Смена прошла успешно, страница не перезапрашивает логин/пароль |
| 2 | На Устройстве Б перейти в защищенный раздел профиля | Запрос отклоняется (HTTP 401 Unauthorized), сессия завершена, открывается экран входа |
