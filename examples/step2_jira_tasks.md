# 📦 Пакет задач Jira (Jira Task Decomposition)

## 1. Обзор эпика (Epic Overview)
- **Epic Key / Name**: `SEC-EPIC-10: Функционал безопасной смены пароля в Личном кабинете`
- **Бизнес-цель**: Предоставить авторизованному пользователю возможность самостоятельного обновления пароля учетной записи в веб-интерфейсе в соответствии со стандартами информационной безопасности.
- **Статус Quality Gate 2**: ✅ **PASSED**

## 2. Декомпозиция пользовательских историй (User Stories)

### [SEC-101] User Story: Форма смены пароля в Личном кабинете (Frontend & Integration)
- **Тип задачи**: User Story
- **Приоритет**: High
- **Компоненты**: `Frontend-Web`, `Security-UI`
- **Описание**:
  > **Как** авторизованный пользователь системы,  
  > **Я хочу** иметь возможность ввести старый пароль, задать новый пароль и подтвердить его на странице безопасности,  
  > **Чтобы** обновить данные аутентификации при необходимости или компрометации старого пароля.

#### Acceptance Criteria (AC):
- **AC-1 (Успешное сохранение нового пароля)**:
  - **Given**: Пользователь авторизован и открыл раздел "Безопасность"
  - **When**: Пользователь вводит верный старый пароль, новый валидный пароль (от 8 до 32 символов, содержащий буквы, цифры и спецсимволы) и идентичное подтверждение
  - **And**: Нажимает кнопку "Сохранить изменения"
  - **Then**: Отображается уведомление зеленого цвета: "Пароль успешно обновлен"
  - **And**: Поля формы очищаются, текущая сессия не прерывается.

- **AC-2 (Инлайн-валидация сложности пароля)**:
  - **Given**: Пользователь находится на форме смены пароля
  - **When**: Пользователь вводит новый пароль менее 8 или более 32 символов, либо без спецсимволов/цифр
  - **Then**: Под полем нового пароля мгновенно отображается подсказка с незакрытыми требованиями:
    - *"Минимум 8 символов"*
    - *"Хотя бы одна цифра"*
    - *"Хотя бы один специальный символ (!@#$%^&*)"*
  - **And**: Кнопка "Сохранить изменения" неактивна (disabled).

- **AC-3 (Совпадение со старым паролем)**:
  - **Given**: Пользователь вводит корректный старый пароль
  - **When**: В качестве нового пароля введен пароль, идентичный старому
  - **Then**: Отображается ошибка: *"Новый пароль не должен совпадать с текущим"*, кнопка отправки заблокирована.

- **AC-4 (Неверный старый пароль)**:
  - **Given**: Пользователь заполнил все поля формы валидными значениями, но старый пароль указан неверно
  - **When**: Пользователь отправляет форму
  - **Then**: Бэкенд возвращает статус `400 Bad Request` с кодом `INVALID_CURRENT_PASSWORD`
  - **And**: В UI отображается сообщение: *"Указан неверный текущий пароль"*.

### [SEC-102] Technical Task: Реализация API смены пароля и инвалидации сторонних сессий (Backend)
- **Тип задачи**: Technical Task
- **Приоритет**: Highest
- **Компоненты**: `Auth-Service`, `Redis-Session`
- **Описание**: Реализовать эндпоинт `PUT /api/v1/auth/password/change`.
- **Критерии завершения**:
  1. Валидация текущего пароля через Argon2id хеш в БД.
  2. Проверка сложности нового пароля регулярным выражением: `^(?=.*[A-Za-z])(?=.*\d)(?=.*[!@#$%^&*()_+=\-{}[\]:;"'<>,.?/]).{8,32}$`.
  3. Проверка на несовпадение старого и нового хешей.
  4. Удаление всех Refresh-сессий данного пользователя из Redis, кроме текущего активного DeviceId.
  5. Генерация аудиторного события `USER_PASSWORD_CHANGED` в Kafka.

---

### [SEC-103] Technical Task: Защита эндпоинта от перебора паролей (Rate Limiting)
- **Тип задачи**: Technical Task
- **Приоритет**: High
- **Компоненты**: `API-Gateway`, `Redis`
- **Описание**: Настроить счетчик неудачных попыток ввода на уровне API Gateway / Redis.
- **Критерии завершения**:
  1. Счетчик привязан к комбинации `UserId + IP-адрес`.
  2. При 5 последовательных ошибках 400 (неверный текущий пароль) в течение 15 минут — возвращать `429 Too Many Requests` с заголовком `Retry-After: 900`.
  3. Успешный ввод пароля сбрасывает счетчик ошибок.
