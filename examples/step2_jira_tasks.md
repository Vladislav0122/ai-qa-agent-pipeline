## 2. Утвержденные задачи спринта (Confirmed Sprint Backlog)

### [SEC-101] User Story: Форма смены пароля в Личном кабинете (Frontend)
- **Тип задачи**: User Story
- **Приоритет**: High
- **Компоненты**: `Frontend-Web`, `Security-UI`
- **Описание**:
  > **Как** авторизованный пользователь системы,  
  > **Я хочу** иметь возможность ввести текущий пароль, задать новый пароль (от 10 символов) и подтвердить его,  
  > **Чтобы** обновить учетные данные без обращения в службу поддержки.

#### Acceptance Criteria (AC):
- **AC-1 (Успешное сохранение нового пароля — Happy Path)**:
  - **Given**: Пользователь авторизован и находится в разделе «Безопасность»
  - **When**: Пользователь вводит верный текущий пароль, новый валидный пароль (от 10 до 32 символов, содержащий буквы, цифры и спецсимволы) и идентичное подтверждение
  - **And**: Нажимает кнопку «Сохранить изменения»
  - **Then**: Отображается уведомление: *"Пароль успешно обновлен"*
  - **And**: Поля формы очищаются, текущая сессия пользователя продолжается без разлогина.

- **AC-2 (Валидация длины и сложности пароля)**:
  - **Given**: Пользователь заполняет поле нового пароля
  - **When**: Пользователь вводит пароль длиной менее 10 или более 32 символов, либо без цифр/спецсимволов
  - **Then**: Под полем мгновенно отображается подсказка:
    - *"Минимальная длина: 10 символов"*
    - *"Обязательно наличие букв, цифр и спецсимволов"*
  - **And**: Кнопка «Сохранить изменения» блокируется (disabled).

- **AC-3 (Запрет совпадения со старым паролем)**:
  - **Given**: Пользователь указал старый пароль
  - **When**: В качестве нового пароля введен тот же самый старый пароль
  - **Then**: Отображается ошибка: *"Новый пароль не должен совпадать с текущим"*, кнопка отправки заблокирована.

- **AC-4 (Обработка неверного текущего пароля)**:
  - **Given**: Пользователь заполнил все поля формы, но текущий пароль указан ошибочно
  - **When**: Пользователь отправляет форму
  - **Then**: Бэкенд возвращает статус `400 Bad Request`
  - **And**: В интерфейсе выводится сообщение: *"Указан неверный текущий пароль"*.

### [SEC-102] Technical Task: Реализация API смены пароля и завершения сторонних сессий (Backend)
- **Тип задачи**: Technical Task
- **Приоритет**: Highest
- **Компоненты**: `Auth-Service`
- **Описание**: Реализовать эндпоинт `PUT /api/v1/auth/password/change`.
- **Критерии завершения (Definition of Done)**:
  1. Валидация текущего пароля пользователя в сервисе аутентификации.
  2. Проверка сложности нового пароля регулярным выражением: `^(?=.*[A-Za-z])(?=.*\d)(?=.*[!@#$%^&*()_+=\-{}[\]:;"'<>,.?/]).{10,32}$` (валидация на 10–32 символа).
  3. Проверка несовпадения старого и нового хеша.
  4. Завершение всех активных сессий пользователя на сторонних устройствах (токены текущей активной сессии перевыпускаются).
  5. Покрытие Unit-тестами >= 85%.
