# SKILL: test_design (Проектирование тест-кейсов)

## 1. Роль и Назначение
Навык отвечает за формирование исчерпывающей тестовой модели на основе декомпозированных задач Jira (`STEP2_JIRA_TASKS.md`) и требований Confluence с учетом замечаний ревью (`STEP1_REQUIREMENT_REVIEW.md`). Результат адаптирован для экспорта/импорта в популярные TMS (Test IT, Allure TestOps, TestRail).

---

## 2. Применяемые техники тест-дизайна (Test Design Techniques)

Для каждого функционального узла обязательно применяются:

### 2.1. Классы эквивалентности (Equivalence Partitioning — EP)
- Разделение всего диапазона входных параметров на классы эквивалентности:
  - Валидный класс (Valid Class)
  - Невалидные классы (Invalid Classes: пустые значения, неверный формат, запрещенные символы).
- Достаточно одного теста на класс для репрезентативной проверки.

### 2.2. Анализ граничных значений (Boundary Value Analysis — BVA)
- Для числовых диапазонов и строк фиксированной длины:
  - `min - 1` (Невалидное значение)
  - `min` (Валидная нижняя граница)
  - `min + 1` (Валидное значение внутри диапазона)
  - `max - 1` (Валидное значение внутри диапазона)
  - `max` (Валидная верхняя граница)
  - `max + 1` (Невалидное значение за верхней границей)

### 2.3. Таблицы решений (Decision Tables)
- Используются при сочетании нескольких условий (например: верный текущий пароль + валидный новый пароль + подтверждение совпадает).

### 2.4. Тестирование перехода состояний (State Transition)
- Проверка жизненного цикла сущности (например: Активен ➔ Заблокирован после 5 неверных попыток ввода ➔ Разблокирован по таймауту).

### 2.5. Предугадывание ошибок и негативные проверки (Error Guessing)
- XSS и SQL инъекции (`<script>`, `' OR '1'='1`).
- Unicode, пробелы (лидирующие, замыкающие, только пробелы), emoji.
- Прерывание интернет-соединения, истечение сессии (Expired JWT), параллельные запросы (Race Conditions).

## 3. Структура тест-кейса для TMS

Каждый тест-кейс должен содержать стандартизированный набор атрибутов:
- **ID / Key**: Уникальный идентификатор (например: `TC-AUTH-001`).
- **Title (Название)**: Четкое действие и ожидаемый результат в повелительном наклонении.
- **Priority**: Critical / High / Medium / Low.
- **Type**: Positive / Negative / Boundary / Security.
- **Layer**: UI / API / Unit / Integration.
- **Traceability Link**: Ссылка на задачу Jira (например: `PROJ-101 (AC-1)`).
- **Preconditions (Предусловия)**: Начальное состояние системы и тестовые данные.
- **Steps & Expected Results**: Пошаговый сценарий действий с однозначным ожидаемым результатом для каждого шага.
- **Postconditions (Постусловия)**: Очистка тестового состояния (при необходимости).

## 4. Критерии Quality Gate 3 (Test Quality Gate)

Перед сохранением артефакта проверяется:
- [x] **Полнота покрытия**: Каждый критерий приемки (AC) покрыт минимум 1 позитивным и 1-2 негативными сценариями.
- [x] **Атомарность**: Один тест-кейс проверяет ровно одну логическую ветвь/поведение.
- [x] **Воспроизводимость**: Шаги написаны детально, без двусмысленностей, с указанием конкретных значений тестовых данных.
- [x] **Разделение слоев**: Выделены как UI-проверки, так и базовые API-проверки (валидация тела запроса и статус-кодов).

## 2. Детальные тест-кейсы для импорта в TMS

### [TC-AUTH-001] Успешная смена пароля пользователем (Happy Path)
- **Приоритет**: Critical
- **Тип**: Positive
- **Слой**: UI
- **Трассировка**: `PROJ-101 -> AC-1`
- **Предусловия**:
  1. Пользователь `test_user@example.com` зарегистрирован и активен.
  2. Пользователь успешно авторизован в системе и находится на странице `/profile/security`.
- **Тестовые данные**:
  - Текущий пароль: `OldPass123!`
  - Новый пароль: `NewSecret2026#`
  - Подтверждение: `NewSecret2026#`

| № | Действие (Step) | Ожидаемый результат (Expected Result) |
|---|---|---|
| 1 | Ввести `OldPass123!` в поле "Текущий пароль" | Значение введено, символы маскируются |
| 2 | Ввести `NewSecret2026#` в поле "Новый пароль" | Индикатор сложности показывает "Надежный пароль" (зеленый) |
| 3 | Ввести `NewSecret2026#` в поле "Повторите пароль" | Поле заполнено, ошибок несовпадения нет |
| 4 | Нажать кнопку "Сохранить изменения" | 1. Отображается системный тост: "Пароль успешно изменен"<br>2. Форма очищается<br>3. Сессия с новым паролем валидна |

- **Предусловия**: Пользователь находится на форме смены пароля.
